# 프론트엔드 오류 안내 및 세션 만료 처리 설계

## 목표

사용자에게 내부 기술 용어를 노출하지 않고 조회 실패 원인을 상황별로 안내한다. 인증 세션이 만료되면 로컬 세션을 정리하고 로그인 화면으로 이동한 뒤 토스트로 재로그인을 안내한다.

## 동작

- API 요청에 사용할 세션이 없거나, 토큰 갱신 후에도 API가 `401`을 반환하면 세션 만료로 처리한다.
- 동시에 여러 요청이 실패해도 로그아웃과 로그인 화면 이동은 한 번만 수행한다.
- 로그인 화면 이동 주소는 `/login?reason=session-expired`를 사용한다.
- 로그인 화면은 `reason`을 읽어 `로그인 시간이 만료되었습니다. 다시 로그인해 주세요.` 토스트를 한 번 표시하고 URL에서 사유를 제거한다.
- `403`은 로그아웃하지 않고 접근 권한 오류로 처리한다.
- 네트워크 오류, 서버 오류, 일반 조회 오류는 사용자가 이해할 수 있는 문구로 구분한다.

## 구성

- `lib/api/error-message.ts`: API 및 네트워크 오류를 사용자 안내 문구로 변환한다.
- `lib/auth/session-expiry.ts`: 세션 만료 이동 주소와 중복 처리 방지 로직을 제공한다.
- `components/ui/toast.tsx`: 기존 디자인 토큰을 사용하는 공통 토스트 UI다.
- 로그인 화면: URL 사유를 토스트로 변환하고 주소를 정리한다.
- 대시보드·문의함·문의 상세·확인 필요 목록: 공통 오류 문구를 사용한다.

## 검증

- 세션 만료 처리가 동시에 호출돼도 로그아웃과 이동이 한 번만 실행되는지 검증한다.
- 로그인 사유가 올바른 토스트 문구로 변환되는지 검증한다.
- 네트워크, `403`, `5xx`, 기타 오류의 안내 문구를 검증한다.
- 전체 프론트엔드 테스트, 린트, 빌드를 실행한다.
